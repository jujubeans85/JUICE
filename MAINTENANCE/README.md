# JUICE maintenance

One collector, one existing portfolio registry, one private monthly record.
The collector uses Python's standard library and GitHub GET requests. It does
not clone or execute audited projects and has no GitHub mutation API.

## What is working

- `portfolio_audit.py` collects public owner repositories, all branch and open-PR
  pages, pinned default-head trees/configuration, branch divergence, workflow
  enablement, the latest 50 Actions runs per repository and current PR commit
  statuses (including external deploy-preview checks).
- The committed [baseline report](baseline/report.md), [short summary](baseline/summary.md)
  and [snapshot](baseline/snapshot.json) establish the first machine-readable
  checkpoint. [baseline/report.html](baseline/report.html) opens offline.
- `portfolio-audit.yml` runs on relevant PRs, manual dispatch and monthly at
  **00:23 UTC on the first** (10:23 AEST / 11:23 AEDT). Reports are run artifacts
  and a concise Actions summary. No source commits, issues or PR comments are
  generated by the workflow.
- JUICE Control's home page links to `/maintenance` and the audit history.
  This source integration does not install anything on the actual Mac.

The workflow is proposed in a review branch. **Monthly GitHub execution starts
only after it is reviewed and merged onto main.** PR execution verifies the
code before that. This maintenance work does not merge it automatically.

## Run and read

```sh
python3 -m unittest discover -s MAINTENANCE/tests -v
python3 MAINTENANCE/portfolio_audit.py --previous-from-actions
```

The live API needs a read credential because an unauthenticated GitHub limit is
too small for the whole portfolio. Actions supplies its short-lived
`GITHUB_TOKEN`; locally reuse an existing `GH_TOKEN`/`GITHUB_TOKEN`. Do not paste
tokens into commands, reports, Git or chat. The tool does not create credentials.

For Control, write the same outputs to its fixed local report location:

```sh
python3 MAINTENANCE/portfolio_audit.py --previous-from-actions \
  --output ~/JUICE_DATA/MAINTENANCE/latest
```

Outputs: `summary.md` (phone-sized changes), `report.html` (expandable evidence),
`report.md` and `snapshot.json` (full public evidence). Raw API captures are never
committed. Replaying initial connector captures requires those private scratch
responses; synthetic tests are self-contained and need no account access.

## Deltas, state and failure handling

Stable finding IDs retain first-seen/last-changed dates. Unchanged findings stay
in history and are not reissued as new tasks. A missing/failed collection never
silently resolves an old finding. The report separates observations,
recommendations and approved changes; the last section stays empty for audits.

Each complete main-branch run saves a `portfolio-state` artifact for 90 days.
The next run restores the newest complete default-branch state. Review and
incomplete artifacts have distinct names and cannot become the baseline.
If state expires or cannot be read, the report explicitly falls back to the
reviewed Git baseline; it never claims month-on-month continuity it did not load.
The private monthly record keeps durable finding history and notes any fallback.
At a deliberately reviewed checkpoint, commit a fresh public baseline to extend
durable machine history; no monthly baseline commits or generated cleanup PRs.

GitHub can disable public schedules after 60 days without repository activity,
and scheduled runs can be delayed/dropped. The existing connected monthly audit
checks workflow freshness (over 40 days is stale), its enabled state where
accessible, and the last successful report. It records one stable blocker when
the workflow is unmerged, disabled or inaccessible, then suppresses repeats.
It can still inspect connected repositories read-only; it does not claim that
the hosted workflow ran. No heartbeat commits or self-modifying cron jobs.

## Cross-repository permissions

The workflow declares only `contents: read` and `actions: read`, uses pinned
checkout/upload actions, disables checkout credential persistence, and never
receives a portfolio secret. Public source is available across repositories;
the built-in token's installation authority is confined to JUICE and **cannot
inspect another private repository**. No private data is put into a public job,
log, artifact, step summary or committed baseline.

**Chosen approach:** zero new credentials. Public source audit in Actions;
restricted metadata in the existing connected monthly audit and private record.
This covers the known 46 with an honest boundary and no PAT expiry chore.

If a fully hosted private audit becomes necessary later, run it from a private
repository with a dedicated GitHub App installed on the selected repositories.
Grant **Metadata, Contents, Pull requests, Actions, Commit statuses: read**.
Use short-lived installation tokens; discover its installation repositories
with pagination. A fine-grained PAT is a simpler manual alternative with the
same read permissions, owner resource selection and explicit expiry/rotation,
but requires the user to create/store it. Never request repository write,
administration, secrets, merge or deployment permission for this audit. This
future setup is documented, not installed or required now.

Primary permission/scheduling references checked during implementation:
[GITHUB_TOKEN scope](https://docs.github.com/en/actions/concepts/security/github_token),
[repository listing](https://docs.github.com/en/rest/repos/repos),
[pull-request permissions](https://docs.github.com/en/rest/pulls/pulls),
[scheduled-workflow inactivity](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/disable-and-enable-workflows),
[workflow triggers](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows).

## Integration and rollback

Chats, ChatGPT projects, pins and full conversation bodies need an actual
supplied export/inventory; retrieval hits are not complete account access.
Library and automation observations stay in the private living record. Mac
files, unpushed commits, services, audio processors, local databases and backups
require an actual Mac connection. Existing Control defaults to 8765; reported
8780 ownership remains unresolved. No installation or runtime repair is claimed.

To roll back this change, close the unmerged PR or revert its eventual merge
commit normally. Restore just the additive Control link/GET route if necessary.
Reports and source history remain available. The workflow can be disabled
without removing evidence. No original project files, research, catalogue,
open branches, existing workflows or deployment settings are removed.
