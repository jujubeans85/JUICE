RESEARCH & IMPLEMENTATION BRIEF / 28 OCTOBER 2026

A world behind
every record.

Build a personal atlas connecting exact recordings to places, moments, people, musical practices and historical circumstances. Let anyone begin with their own library and hear examples along the way. Start with Juice J’s CRATE JUICE catalogue.

The recommendation

Use a shared, evidence-backed music-history graph with a private listening layer for each person. Reuse the AFTERWORLD globe foundations. Start with a modular application and relational database; add a specialist graph database only if measured query costs justify it. Research once, reuse across recordings and listeners.

The difficult part is the historical evidence and the recording identity. A beautiful globe is the visible part.

Imported music → a growing globe · 29 October 2026

Import & research → maintains an ordered, resumable library queue. Every imported recording receives a stable root. New IDs and corrected credits enter automatic research; repeat imports retain completed work and duplicate crate memberships. Only one tab owns the research writer at a time. Checkpoints survive reopening; pause/resume controls are shared between the importer and globe. Research runs while a page is open.

The first pass resolves an exact musical creator or a clearly labelled source display-credit context, retrieves revision-linked Wikipedia material and Wikidata geography/date roles, and follows an explicit genre link when available. Shared facts can serve many recordings. A source uploader is never silently declared the performer, an artist’s birthplace is never a recording location, and an article link is never certified as ancestry. The review panel accepts a listener-selected musical subject when source identity is ambiguous. From any resulting point, the existing on-demand threads continue deeper.

The public Git archive contains public memberships only. The existing owner-private Site overlays private source snapshots and generates owner-complete offline/text copies. Four sources currently declare zero tracks; those are verified empty snapshots, not reconstructed histories. No provider audio, authorisation tokens or secret share URLs are archived. Exact native recording links remain available; embeds can require source access or provide only previews.

Atlas v3 exports include structured crate snapshots, automatic jobs/graph and on-demand exploration. Browser persistence remains local and evictable, so exports provide an independent copy. New music is queued as imported; this release does not monitor platform accounts for future changes, run while closed, or publish newly retrieved context as reviewed history.

On-demand exploration · 29 October 2026

The atlas now expands from the selected point at runtime. Seven threads cover politics, divergence, other recordings, people, places, instruments and technology/media. Each request reads live source material; connections are not prewritten individually. A newly opened branch becomes the next starting point, so the interaction has no fixed depth. Users can retrace or revisit branches, refresh a source, start another music topic, or export and restore the explored graph.

This release uses English Wikipedia article links and musical source passages, plus Wikimedia Commons audio search and videos linked by the source article. It is source retrieval and graph expansion, not an AI service inventing ancestry. Results are explicitly source-linked context. A hyperlink or search match does not demonstrate musical influence, style descent, political causation or an exact recording match.

On a general historical or political page, further branches must remain in musical text or a musical section. If the source yields no qualifying connection, the interface says so; it does not continue through unrelated people, wars or countries. These are conservative text heuristics and can miss or misclassify links. Original references attached to a source passage are exposed when available, and every live branch retains its article revision, excerpt, relationship and retrieval date for review.

Only clicked branches are added to your explored graph. IndexedDB retains that graph on this browser, with an in-session fallback if storage is unavailable. Source responses are cached for 24 hours; failed refreshes retain a labelled stale copy. Export atlas includes the graph and restoring that export merges stable node IDs. Browser storage is evictable and does not provide cross-device sync. Live results do not update the canonical catalogue, public Git repository or reviewed history automatically.

Commons audio retains its source page, creator and item-level licence; video candidates retain exact provider IDs and are labelled unverified. The player loads only on a deliberate play action. An audio search hit is not automatically an example from the same time, location or musical style, and unavailable audio is not silently replaced. No paid model API or new backend service is required by this implementation.

Implementation: separate source adapters, pure music-relevance/graph contracts and a UI controller share the existing globe, player and history model. Provider URLs are fixed, requests omit credentials, source HTML is parsed without inserting it into the page, outputs are escaped, and source requests have time/size budgets. English source coverage, metadata gaps, source availability, browser storage and heuristic relevance remain practical limits.

The experience worth building

  1. Begin with a recording you recognise. Display the precise live performance, mix or edit you saved. Keep the track playing while the user chooses which thread to follow; one active player at a time.
  2. Choose a thread. Rhythm, voice, melody/harmony, instrument, recording technology, people, migration, politics, film/advertising or a local scene. A genre label is one entry point, not an origin certificate.
  3. Move through place and time. Show cities, regions and diasporas as appropriate. Distinguish birthplace, childhood, scene affiliation, composition setting, studio, performance, release market and later reception. Do not reduce a multinational band to one nationality.
  4. Hear the change. Pair a documented earlier recording with the exact later recording. Label a period performance, later traditional rendition, modern reconstruction and illustrative example differently. Eventually add source timestamps and an explanation of the audible feature.
  5. Open the evidence. Every relationship answers “what connects these?” with a source and a claim type. Context branches can be turned off. A sequence of cards does not itself prove a causal chain.
  6. Discover beyond your lane. Offer a documented ancestor, a sibling reinterpretation, a descendant and a contrasting tradition. Explain the selection; avoid trapping people inside one inferred taste profile.

The globe should support the story. On a phone, the timeline and readable evidence cards must remain usable without rotating Earth. A normal search/list interface and accessible linear reading are first-class views.

One history graph. Many private libraries.

The graph is a model of claims, not a collection of AI-written biographies. Start with PostgreSQL tables and explicit relationships. PostGIS handles geographic footprints and spatial queries; recursive queries handle bounded history paths. Indexed JSON exports serve the first static edition. This is an architecture recommendation, not a deployed database.

A relationship should look like: “this 2017 performance covers this composition”, or “this artist names this musician as an influence”. A war, political campaign or advertisement is linked only through a specific supported relationship—commission, use, lyric reference, ban, performance, scene conditions or documented response. Being alive during an event does not prove it shaped a song.

Use stable shared entity IDs, with mappings back to existing CJ identifiers. Keep uncertainty and source revisions append-only where practical. Do not maintain separate competing catalogues inside the globe, a playlist service and a research document.

How the history earns its place

Relationship statusMeaningPresentation
DocumentedA source supports the specific relationship: credit, cover, sample, contemporary document or stated influence.Solid edge and exact claim wording. An interview proves the artist said it; it does not independently verify every recollection.
Historical contextA sourced event or tradition is relevant background, without a proved direct connection to the track.Dashed, optional branch. No transitive “therefore influenced” conclusion.
Hypothesis / musical resemblanceAn editorial or analytical lead awaiting historical support.Separate discovery layer, excluded from documented ancestry. None is promoted as fact in this pilot.
Disputed / unknownSources conflict, attribution is contested, or evidence is absent.Show alternatives or an unresolved gap. A low-precision date/region must not become an exact year/pin.

Prefer artist interviews, session and publishing credits, contemporaneous newspapers, oral histories, community archives, museum collections and specialist scholarship. Search in relevant languages and include local scholars and cultural custodians. MusicBrainz and Wikidata help resolve identities and locate leads; they do not replace musicological evidence.

Do not force every recording back to one ancient origin. Influence is many-to-many, traditions evolve without surviving recordings, and histories of displacement are not neat arrows between modern countries. A library can ultimately link to centuries of history without pretending every incremental change is recoverable.

For periods before sound recording, use dated scores, instruments, oral-history accounts and carefully labelled present-day demonstrations. Never label a modern traditional performance as “the sound of 1700”. The 1773 text event in this pilot has no verified period audio; the 1835 melody demonstration explicitly says it is modern synthesis.

Respect community-specific access and reuse conditions, including the Local Contexts TK Labels where applicable. An archive’s possession of a recording does not by itself resolve cultural authority or permission to reproduce it.

Research findings from the first three routes

  • Porter’s family and church background is documented. His mother Ruth matters to the history, alongside Cole and Sting. The older hymn/spiritual material is marked as context rather than a proven uninterrupted genealogy.
  • Tom’s Diner branches into multiple versions and a technological use. DNA and the German cover share a work, but no evidence here establishes the cover as a child of DNA’s arrangement. Fraunhofer’s first-person account supports the compression branch.
  • Changes connects a piano-led 1972 rock recording to Bradley’s reinterpretation and a network of working producers. The Black Sabbath album sessions were in Los Angeles; that pin must not be mistaken for the band’s origin.
  • Source prestige is not a substitute for cross-checking. The Library of Congress Vega essay contains chronology problems, and Sting’s release page includes an apparently erroneous live-performance date. Those details are excluded; source notes retain the conflicts.

Do not build the company around assumed Spotify access

Spotify’s current quota rules limit new development-mode apps to five authenticated users, require the owner to have Premium, and restrict extended-access applications to organisations meeting eligibility conditions. This is not an automatic route from a personal prototype to a public product.

The Developer Policy also restricts analysis/profiling, AI ingestion, cross-service integrations and commercial streaming applications. Before any live integration, review the precise proposed use and obtain appropriate rights/access. User-provided exports, independent history research and authorised-file audio analysis need their own provenance and permissions; an export is not a blanket licensing workaround. This pilot makes no Spotify API calls.

Prioritise work by reusable history: a documented producer, instrument technique or regional scene can enrich many tracks. Cache shared graph fragments. Keep a bounded traversal per interaction; render clusters when zoomed out and reveal events as users focus. Partition private observations by user and time. A long history need not become a giant ball of lines.

Research is the likely variable cost. Estimate it from a timed benchmark, including identity resolution, conflicting sources, example verification and review. Do not quote a credible all-library completion time from playlist count alone. Track cost per approved claim, per newly covered recording and per reusable history branch.

Quality gates

  • Recording identity: no silent live/studio/remix substitutions; source IDs survive every import/export.
  • History: every asserted edge has evidence; automatically inferred transitive influences stay excluded. Review random paths and important disputed claims.
  • Playback: exact source, one player at a time, visible unavailable state and native fallback. Check actual listening in the relevant territory before marking playback-checked.
  • Geography/time: date intervals, representative anchors, unsited and undated events survive round trips. No modern borders presented as historical cultural boundaries.
  • Personalisation: user explanation and correction matter. Listen count, skip count and save count are signals with ambiguity, not proof of taste or its causes.
  • Performance/accessibility: iPhone Safari, keyboard/screen reader, reduced motion, WebGL failure, offline catalogue and a readable timeline. Set measured device budgets before larger rollout.

Import-time concept engine

Each imported exact recording now receives a local concept check. The matching desk shows reviewed fits, contextual suggestions, open questions and explicit user choices. The shared registry contains ten visual families and 32 scene editions, with references from the visual research pass.

Matching starts with exact source, artist and work identity. It then considers structured genres, formats, instruments and scene labels; specific concepts take precedence over generic fallbacks. Close competitors remain reviewable. Every recording keeps its source, version and date roles, and unfamiliar genre labels remain visible even before a matching visual rule is added.

Optional online work resolves named artist topics on Wikipedia and reuses structured genre context across recordings. It does not analyse audio, infer causal ancestry, substitute another performance or treat a nationality as a visual culture. Eight artists are checked per batch; cached context, pause and continuation keep the work bounded. Local matches and manual choices work offline.

The same resolved style drives the WebGL and compatibility globes. Patterns are editorial references rather than claims about archival capture. Your appearance lock takes precedence. Atlas exports now include concept decisions and cached artist context; prior v2 exports still restore.
